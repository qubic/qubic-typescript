`createQubicClient` is the easiest way to get started. It creates both a live and archive client in one call, sharing the same fetch and abort configuration. The polling helpers cover the confirmation workflow after you broadcast a transaction.

All four functions return the `Result<T, E>` type from `@qubic.org/rpc`: `{ ok: true, value }` on success, `{ ok: false, error }` on failure.

## `createQubicClient(options?)`

Creates a `QubicClient` with `.live` (live API) and `.archive` (query API) sub-clients.

```ts
import { createQubicClient } from "@qubic.org/rpc"

const client = createQubicClient()

const tickResult = await client.live.getTickInfo()
if (tickResult.ok) console.log(tickResult.value.tick)
```

Use this instead of calling `createLiveClient` and `createQueryClient` separately when you need both.

**Parameters**

| Name | Type | Description |
|---|---|---|
| `liveBaseUrl` | `string` | Override the live API base URL. Default: `https://rpc.qubic.org/live/v1` |
| `archiveBaseUrl` | `string` | Override the archive API base URL. Default: `https://rpc.qubic.org/query/v1` |
| `signal` | `AbortSignal` | Applied to every request on both sub-clients |
| `fetch` | `(input: Request) => Promise<Response>` | Custom fetch implementation |

**Returns** `QubicClient` — an object with `live: LiveClient` and `archive: QueryClient`.

## `waitForTick(live, targetTick, options?)`

Polls `live.getTickInfo()` until the network tick reaches or exceeds `targetTick`. Returns when the condition is met or the timeout expires.

```ts
import { createQubicClient, waitForTick } from "@qubic.org/rpc"

const { live } = createQubicClient()

const tickResult = await live.getTickInfo()
if (!tickResult.ok) throw tickResult.error

const target = tickResult.value.tick + 5

const confirmation = await waitForTick(live, target, { timeoutMs: 90_000 })
if (confirmation.ok) {
  console.log("Tick reached:", confirmation.value)
}
```

**Parameters**

| Name | Type | Description |
|---|---|---|
| `live` | `LiveClient` | Live client to poll |
| `targetTick` | `number` | Tick number to wait for |
| `intervalMs` | `number` | Poll interval in milliseconds. Default: `1000` |
| `timeoutMs` | `number` | Maximum wait in milliseconds. Default: `60000` |
| `signal` | `AbortSignal` | Cancels polling when aborted |

**Returns** `Promise<Result<number, QubicRpcError>>` — `ok(targetTick)` when reached, `err` on timeout or cancellation.

---

## `pollUntilConfirmed(live, targetTick, options?)`

Waits until the network tick passes `targetTick`, confirming that a submitted transaction has been included. This is equivalent to `waitForTick(live, targetTick + 1)`.

Qubic executes transactions in a specific tick. A transaction is confirmed when the network has moved past that tick.

```ts
import { createQubicClient, pollUntilConfirmed, estimateTargetTick } from "@qubic.org/rpc"

const { live } = createQubicClient()

// Get current tick and estimate where to submit
const tickResult = await live.getTickInfo()
if (!tickResult.ok) throw tickResult.error
const targetTick = estimateTargetTick(tickResult.value.tick)

// ... build and broadcast transaction with targetTick ...

// Wait for confirmation
const confirmed = await pollUntilConfirmed(live, targetTick, { timeoutMs: 120_000 })
if (!confirmed.ok) {
  console.error("Confirmation timed out:", confirmed.error.message)
}
```

**Parameters**

| Name | Type | Description |
|---|---|---|
| `live` | `LiveClient` | Live client to poll |
| `targetTick` | `number` | The tick number the transaction was submitted for |
| `intervalMs` | `number` | Poll interval in milliseconds. Default: `1000` |
| `timeoutMs` | `number` | Maximum wait in milliseconds. Default: `60000` |
| `signal` | `AbortSignal` | Cancels polling when aborted |

**Returns** `Promise<Result<number, QubicRpcError>>` — `ok(targetTick)` when the tick passes, `err` on timeout or cancellation.

## `estimateTargetTick(currentTick, offsetTicks?)`

Returns `currentTick + offsetTicks` as the recommended tick to include in a submitted transaction.

Qubic requires each transaction to declare a target tick. Setting it too close to the current tick risks the transaction arriving too late. The default offset of `5` gives approximately five seconds of buffer at standard tick rates.

```ts
import { estimateTargetTick } from "@qubic.org/rpc"

const targetTick = estimateTargetTick(currentTick)       // currentTick + 5
const furtherOut = estimateTargetTick(currentTick, 10)   // currentTick + 10
```

**Parameters**

| Name | Type | Description |
|---|---|---|
| `currentTick` | `number` | The current tick from `getTickInfo()` |
| `offsetTicks` | `number` | Ticks to add. Default: `5` |

**Returns** `number` — the target tick.

## Send and confirm workflow

This example assembles all four utilities into a complete send-and-confirm flow.

```ts
import {
  createQubicClient,
  estimateTargetTick,
  pollUntilConfirmed,
} from "@qubic.org/rpc"
import { buildTransaction, signTransaction } from "@qubic.org/tx"

const { live, archive } = createQubicClient()

// 1. Get current tick
const tickResult = await live.getTickInfo()
if (!tickResult.ok) throw tickResult.error
const targetTick = estimateTargetTick(tickResult.value.tick)

// 2. Build and sign
const tx = buildTransaction({ source, destination, amount, targetTick })
const signed = signTransaction(tx, privateKey)

// 3. Broadcast
const broadcastResult = await live.broadcastTransaction(signed.encodedTransaction)
if (!broadcastResult.ok) throw broadcastResult.error
console.log(`Broadcast to ${broadcastResult.value.peersBroadcastedTo} peers`)

// 4. Wait for confirmation
const confirmed = await pollUntilConfirmed(live, targetTick, { timeoutMs: 120_000 })
if (!confirmed.ok) {
  console.error("Transaction did not confirm:", confirmed.error.message)
  process.exit(1)
}

// 5. Verify in archive
const txRecord = await archive.getTransactionByHash(signed.hash)
if (txRecord.ok) {
  console.log("Confirmed in tick", txRecord.value.tick)
}
```
