## Overview

Every event has the same outer structure:

```ts
{
  logType: number   // LOG_TYPE constant
  tick: number      // tick where this event occurred
  txId: string      // transaction hash that produced this event
  data: EventData   // type-specific fields (narrowed by logType)
}
```

Decode a raw `RawQubicLogEvent` to get this structure:

```ts
import { decodeEvent } from "@qubic.org/events"
const typed = decodeEvent(rawEvent)
```

---

## QU transfer events

### `QU_TRANSFER` (0)

Fires when QU moves from one identity to another.

```ts
typed.data.source       // Identity — sender
typed.data.destination  // Identity — recipient
typed.data.amount       // bigint — QU transferred
```

## Asset events

### `ASSET_ISSUANCE` (1)

Fires when a new asset is issued.

```ts
typed.data.issuer             // Identity — issuing identity
typed.data.assetName          // string — asset ticker / name
typed.data.numberOfShares     // bigint — total supply issued
typed.data.unitOfMeasurement  // string — unit label
```

### `ASSET_OWNERSHIP_CHANGE` (2)

Fires when ownership of an asset transfers.

```ts
typed.data.issuer          // Identity
typed.data.assetName       // string
typed.data.source          // Identity — previous owner
typed.data.destination     // Identity — new owner
typed.data.numberOfShares  // bigint — shares transferred
```

### `ASSET_POSSESSION_CHANGE` (3)

Fires when possession (not ownership) of an asset transfers. Qubic distinguishes ownership (long-term) from possession (short-term control).

```ts
typed.data.issuer           // Identity
typed.data.assetName        // string
typed.data.source           // Identity — previous possessor
typed.data.destination      // Identity — new possessor
typed.data.numberOfShares   // bigint
```

### `ASSET_OWNERSHIP_MANAGING_CONTRACT_CHANGE` (11)

Fires when the contract managing ownership transfers for an asset changes.

```ts
typed.data.owner                    // Identity
typed.data.issuer                   // Identity
typed.data.assetName                // string
typed.data.sourceContractIndex      // number — previous managing contract
typed.data.destinationContractIndex // number — new managing contract
typed.data.numberOfShares           // bigint
```

### `ASSET_POSSESSION_MANAGING_CONTRACT_CHANGE` (12)

Same as above, but for possession management.

```ts
typed.data.possessor                // Identity
typed.data.owner                    // Identity
typed.data.issuer                   // Identity
typed.data.assetName                // string
typed.data.sourceContractIndex      // number — previous managing contract
typed.data.destinationContractIndex // number — new managing contract
typed.data.numberOfShares           // bigint
```

## Contract message events

All four contract message types share the same data shape:

### `CONTRACT_ERROR_MESSAGE` (4)
### `CONTRACT_WARNING_MESSAGE` (5)
### `CONTRACT_INFORMATION_MESSAGE` (6)
### `CONTRACT_DEBUG_MESSAGE` (7)

```ts
typed.data.contractIndex       // number — which contract emitted the log
typed.data.contractMessageType // number — contract-defined message type code
```

```ts
import { LOG_TYPE } from "@qubic.org/events"

if (typed.logType === LOG_TYPE.CONTRACT_ERROR_MESSAGE) {
  console.error(`Contract ${typed.data.contractIndex} message type ${typed.data.contractMessageType}`)
}
```

## Burn events

### `BURNING` (8)

Fires when an identity burns QU (sends to the zero address or a designated burn address).

```ts
typed.data.source         // Identity — who burned
typed.data.amount         // bigint — QU burned
typed.data.contractIndex  // number — contract that triggered the burn
```

### `DUST_BURNING` (9)

Fires when the network performs a dust-clearing sweep. Small balances below the dust threshold are burned in bulk.

```ts
typed.data.burns  // Array<{ source: Identity; amount: bigint }> — per-account burn entries
```

---

## Network stats events

### `SPECTRUM_STATS` (10)

Fires periodically with a snapshot of the network's balance distribution.

```ts
typed.data.totalAmount             // bigint — total QU in circulation
typed.data.dustThresholdBurnAll    // bigint — below this, entire balance is burned
typed.data.dustThresholdBurnHalf   // bigint — below this, half the balance is burned
typed.data.numberOfEntities        // number — number of accounts above threshold
```

## Other events

### `CONTRACT_RESERVE_DEDUCTION` (13)

Fires when a contract's reserve is reduced.

```ts
typed.data.contractIndex   // number
typed.data.deductedAmount  // bigint — QU deducted from reserve
typed.data.remainingAmount // bigint — reserve balance after deduction
```

### `ORACLE_QUERY_STATUS_CHANGE` (14)

Fires when an oracle query changes status.

```ts
typed.data.queryingEntity  // Identity — entity that submitted the query
typed.data.queryId         // bigint — unique query identifier
typed.data.interfaceIndex  // number — oracle interface
typed.data.queryType       // number — type of query
typed.data.queryStatus     // number — new status code
```

### `ORACLE_SUBSCRIBER_LOG_MESSAGE` (15)

Fires when an oracle subscriber emits a log message.

```ts
typed.data.subscriptionId       // number
typed.data.interfaceIndex       // number
typed.data.contractIndex        // number
typed.data.periodMillis         // number — poll period in milliseconds
typed.data.firstQueryTimestamp  // bigint — timestamp of first query
```

### `CUSTOM_MESSAGE` (255)

Fires for structured custom messages from the core node. The `data` field is decoded into a `CustomMessageData` object with an 8-byte operation code and remaining payload.

```ts
if (typed.logType === LOG_TYPE.CUSTOM_MESSAGE) {
  typed.data.messageType  // bigint — 8-byte operation code
  typed.data.payload       // Uint8Array — remaining payload bytes
}
```

Use `CUSTOM_MESSAGE_TYPE` from `@qubic.org/events` to match known custom message types:

```ts
import { CUSTOM_MESSAGE_TYPE } from "@qubic.org/events"

if (typed.data.messageType === CUSTOM_MESSAGE_TYPE.START_EPOCH) {
  console.log("Epoch started at tick", typed.tick)
} else if (typed.data.messageType === CUSTOM_MESSAGE_TYPE.START_DISTRIBUTE_DIVIDENDS) {
  console.log("Dividend distribution started at tick", typed.tick)
}
```

### `CustomMessageData` type

```ts
interface CustomMessageData {
  messageType: bigint      // 8-byte operation code
  payload: Uint8Array      // remaining bytes after the type field
}
```

The `CUSTOM_MESSAGE_TYPE` constant provides named values:

| Name | Value | Description |
|---|---|---|
| `START_EPOCH` | `4850183582582395987n` | Epoch transition: start of a new epoch |
| `END_EPOCH` | `4850183582582591045n` | Epoch transition: end of current epoch |
| `START_DISTRIBUTE_DIVIDENDS` | `6217575821008262227n` | Dividend distribution started |
| `END_DISTRIBUTE_DIVIDENDS` | `6217575821008457285n` | Dividend distribution ended |

## Filtering by type

Use `eventFilter().ofTypes(...)` to subscribe only to specific log types:

```ts
import { createBobClient } from "@qubic.org/bob"
import { eventFilter, subscribeAllEvents, LOG_TYPE } from "@qubic.org/events"

const bob = createBobClient()

const filter = eventFilter()
  .ofTypes(LOG_TYPE.QU_TRANSFER, LOG_TYPE.ASSET_OWNERSHIP_CHANGE)
  .build()

for await (const event of subscribeAllEvents(bob.subscription, filter)) {
  if (event.isCatchUp) continue
  console.log(event.logType, event.data)
}
```
