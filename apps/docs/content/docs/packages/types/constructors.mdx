title: Constructors
description: toIdentity, toSeed, toTxHash, toBase64 — validate and brand raw strings at your application's boundaries.
---

Use these at the edges of your app: reading from user input, parsing an API response, pulling from environment variables. They validate format and return a branded type, or throw a typed error if the string doesn't conform.

## `toIdentity(s)`

Validates that `s` is exactly 60 uppercase characters, then brands it as `Identity`.

```ts
import { toIdentity } from "@qubic.org/types"

const id = toIdentity("CFBMEMZOIDEXQAUXYYSZIURADQLAPWPMNJXQSNVQZAHYVOPYUKKJBJUCTVJL")
// id: Identity — safe to pass to identityToPublicKey, buildTransaction, etc.
```

**Parameters**

| Name | Type | Description |
|---|---|---|
| `s` | `string` | Candidate identity string |

**Returns** `Identity` — the same string, narrowed to the branded type.

**Throws** `InvalidIdentityError` — if `s` is not exactly 60 uppercase characters.

---

## `toSeed(s)`

Validates that `s` is exactly 55 lowercase characters, then brands it as `Seed`.

```ts
import { toSeed } from "@qubic.org/types"

const seed = toSeed(process.env.WALLET_SEED!)
// seed: Seed — safe to pass to publicKeyFromSeed, signTransaction, etc.
```

**Parameters**

| Name | Type | Description |
|---|---|---|
| `s` | `string` | Candidate seed string |

**Returns** `Seed`

**Throws** `InvalidSeedError` — if `s` is not exactly 55 lowercase characters.

---

## `toTxHash(s)`

Validates that `s` is exactly 60 lowercase characters, then brands it as `TxHash`.

```ts
import { toTxHash } from "@qubic.org/types"

const hash = toTxHash(apiResponse.txId)
```

<Callout>
  Transaction hashes from some API responses come back uppercase. Call `.toLowerCase()` before passing to `toTxHash`.
</Callout>

**Parameters**

| Name | Type | Description |
|---|---|---|
| `s` | `string` | Candidate transaction hash string |

**Returns** `TxHash`

**Throws** `InvalidTxHashError` — if `s` is not exactly 60 lowercase characters.

---

## `toBase64(s)`

Validates that `s` is well-formed standard base64 (alphabet `A-Za-z0-9+/`, optional `=` padding, length divisible by 4), then brands it as `Base64`.

```ts
import { toBase64 } from "@qubic.org/types"

const encoded = toBase64(req.body.signedTransaction)
await live.broadcastTransaction(encoded)
```

**Parameters**

| Name | Type | Description |
|---|---|---|
| `s` | `string` | Candidate base64 string |

**Returns** `Base64`

**Throws** `InvalidBase64Error` — if `s` is not valid standard base64.

---

## Combined pattern: parsing form input

A typical flow — take four raw strings from a form submission, validate all of them before doing anything else:

```ts
import { toIdentity, toSeed, toTxHash, toBase64 } from "@qubic.org/types"
import { InvalidIdentityError, InvalidSeedError, InvalidTxHashError, InvalidBase64Error } from "@qubic.org/types"

function parseTransferForm(form: {
  recipient: string
  seed: string
  previousTxHash: string
  encodedTx: string
}) {
  // All four throw immediately if the format is wrong.
  // The calling code handles each error type separately for user-facing messages.
  const recipient = toIdentity(form.recipient)
  const seed = toSeed(form.seed)
  const previousTxHash = toTxHash(form.previousTxHash.toLowerCase())
  const encodedTx = toBase64(form.encodedTx)

  return { recipient, seed, previousTxHash, encodedTx }
}

// In a request handler:
try {
  const parsed = parseTransferForm(req.body)
  await submitTransfer(parsed)
} catch (e) {
  if (e instanceof InvalidIdentityError) {
    return res.status(400).json({ field: "recipient", message: "Invalid identity format" })
  }
  if (e instanceof InvalidSeedError) {
    return res.status(400).json({ field: "seed", message: "Invalid seed format" })
  }
  throw e
}
```
