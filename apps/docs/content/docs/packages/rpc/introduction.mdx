---
title: Introduction
description: What @qubic.org/rpc is, why it exists, and when to reach for it.
---

`@qubic.org/rpc` is the primary HTTP client layer for the Qubic TypeScript SDK. It wraps the Qubic live RPC gateway and the archive indexer behind two typed clients — `createLiveClient` and `createQueryClient` — so you can query balances, broadcast transactions, and look up historical data without writing a single `fetch` call by hand.

The package was built to solve two problems that come up immediately when working with Qubic over HTTP: the gateway and the archive have different base URLs and different response shapes, and handling every possible failure mode inline makes application code noisy fast. `@qubic.org/rpc` gives you one consistent error type (`QubicRpcError`), full TypeScript inference on every response, and sensible defaults so you can start querying with a single import.

The live client (`createLiveClient`) talks to the real-time RPC gateway. It covers everything that reflects the current state of the network: the active tick, account balances, asset ownership, computor lists, smart contract queries, and transaction broadcast. The archive client (`createQueryClient`) talks to the indexer. It covers everything that requires looking back in time: transaction history, tick data, event logs, and computor epoch history. A combined `createQubicClient` factory gives you both under one handle.

Reach for `@qubic.org/rpc` for one-shot queries, server-side scripts, and any workflow that does not need a persistent connection. If you need to react to every new tick as it arrives, `@qubic.org/bob` is the better fit — it keeps a WebSocket open and pushes updates to your callbacks. The two packages complement each other and are designed to be used together.
