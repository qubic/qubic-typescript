---
title: buildTransaction
description: Construct the unsigned binary header for a Qubic transaction.
---

`buildTransaction` serializes a transaction header into 80 bytes (plus optional payload). The result is unsigned — pass it to `signTransaction` next.

## `buildTransaction(params)`

```ts
import { buildTransaction } from "@qubic.org/tx"
import { toSeed, toIdentity } from "@qubic.org/types"

const seed = toSeed("...")
const recipient = toIdentity("CFBMEMZOIDEXQAUXYYSZIURADQLAPWPMNJXQSNVQZAHYVOPYUKKJBJUCTVJL")

const unsigned = buildTransaction({
  source: seed,               // Identity string
  destination: recipient,     // Identity string (or Uint8Array public key)
  amount: 1_000_000n,
  targetTick: currentTick + 5,
  inputType: 0,               // 0 = plain transfer
})
// unsigned is Uint8Array (80 bytes for a plain transfer)
```

**Parameters**

| Name | Type | Description |
|---|---|---|
| `source` | `Identity \| Uint8Array` | Sender identifier — 60-char uppercase Identity or 32-byte public key |
| `destination` | `Identity \| Uint8Array` | Recipient identifier — 60-char uppercase Identity or 32-byte public key |
| `amount` | `bigint` | Transfer amount in QU |
| `targetTick` | `number` | Tick by which the node must process the transaction |
| `inputType` | `number` | 0 for transfers; procedure index for contract calls |
| `payload` | `Uint8Array \| undefined` | Optional payload bytes for contract calls; byte length is inferred automatically |
| `currentTick` | `number \| undefined` | Optional current tick; when provided, throws `TickInThePastError` if `targetTick <= currentTick` |

**Returns** `Uint8Array` — 80-byte header (+ payload bytes, if any).

---

## Target tick

`targetTick` is a deadline, not a schedule. The network rejects the transaction if the current tick has already passed `targetTick` when the node processes it. If `targetTick` is in the future, the node will process the transaction when it reaches that tick — or drop it after a grace period.

```ts
const tickResult = await live.getTickInfo()
if (!tickResult.ok) throw tickResult.error
const { tick } = tickResult.value
const targetTick = tick + 5  // deadline: process within the next 5 ticks
```

Setting `targetTick` too low (e.g. `tick + 1`) risks rejection if the network is even slightly ahead of your clock. Setting it higher (e.g. `tick + 20`) gives more leeway but means the transaction sits pending longer before expiring if something goes wrong. A buffer of 5–20 ticks is a reasonable default for most conditions.

## Header field layout

| Field | Offset | Size | Description |
|---|---|---|---|
| `sourcePublicKey` | 0 | 32 B | Sender FourQ public key |
| `destinationPublicKey` | 32 | 32 B | Recipient FourQ public key |
| `amount` | 64 | 8 B (LE) | QU amount as little-endian int64 |
| `targetTick` | 72 | 4 B (LE) | Target tick as little-endian uint32 |
| `inputType` | 76 | 2 B (LE) | Procedure index |
| `inputSize` | 78 | 2 B (LE) | Payload byte length |

---

## Plain transfer vs contract call

For a **plain transfer** (identity to identity):
- `destination` = recipient's `Identity` or their 32-byte public key
- `inputType` = `0`
- `inputSize` = `0`, no `payload`

For a **contract call** (SC transaction):
- `destination` = the contract's `Identity` (or 32 zero bytes via `new Uint8Array(32)`)
- `inputType` = the procedure's input type constant
- `payload` = encoded procedure input from a `build*Input` function (`inputSize` is computed automatically)
