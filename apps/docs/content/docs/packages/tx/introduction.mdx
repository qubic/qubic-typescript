---
title: Introduction
description: What @qubic.org/tx does, the transaction lifecycle it implements, and when to use it over @qubic.org/wallet.
---

`@qubic.org/tx` is the low-level transaction layer of the Qubic TypeScript SDK. It builds the binary wire format that the Qubic network expects, signs transactions with SchnorrQ, and encodes the result to base64 for the HTTP broadcast endpoint. It also provides a typed payload codec for structured smart contract inputs.

A Qubic transaction goes through four steps before it can be broadcast. First, `buildTransaction` assembles a binary header from the source public key, destination public key, amount, target tick, and input type. Second, `signTransaction` computes a K12 digest of that header and signs it with the source seed via SchnorrQ, producing the 64-byte signature that gets appended to the transaction bytes. Third, `encodeTransaction` base64-encodes the signed binary into a string the RPC layer accepts. Fourth, that string is passed to the broadcast endpoint. The package also exposes `hashTransaction` and `verifyTransaction` for inspecting transactions you have received rather than built.

For smart contract calls, transactions carry a binary payload describing the contract inputs. `buildPayload` lets you construct those payloads field by field without needing a full ABI registry. For ABI-driven encoding, the higher-level `@qubic.org/contracts` package generates typed wrappers automatically.

Most applications should use `@qubic.org/wallet` instead, which wraps the build–sign–encode pipeline into a single `buildTransfer` or `buildScTransaction` call. Reach for `@qubic.org/tx` directly when you need fine-grained control over the binary format, are building tooling outside the wallet abstraction, or are implementing a custom signing flow.
